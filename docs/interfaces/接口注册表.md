## 二、现状判断

**7 条跨模块调用全部有契约文件：M1 侧 2 条已冻结，D 侧 5 条为草案待责任人确认。**

六个人里面，B/C/D 三个人的跨模块调用方向已经有了规矩（都指向 M1 的那一个接口）。D 侧五条草案也已起草完毕（d-auth / d-space-master-data / d-notification / d-audit / d-config-parameter），**卡点从「没有契约」变成了「责任人未确认」**——A 确认 D-001/D-005、E 确认 D-002（含 ADR-001 教室状态归属）、C 确认 D-003（含批量通知）。

这里面有三条是硬风险，因为它们卡开发：

| 待确认项 | 为什么卡人 |
|---|---|
| **D-002 主数据** | B 要查教室和座位，但主数据在 E 那里、在 `common` schema。B 不能跨 schema 查 → **E 不确认，B 的 `GET /api/m1/seats` 实际上做不出来** |
| **D-005 参数** | 预约时长、提前期等 8 个参数都在草案里，A 不确认 D-005 是否进本轮范围 → B 只能写死 |
| **D-001 鉴权** | 四个服务怎么校验 JWT（JWKS？内省？）没定 → 每个服务会各自实现一套，最后四份不一致 |

**结论：契约本身是稳的，但它只是一块拼图。真正的卡点是草案确认——确认之前，谁先动手谁就有可能按将被修改的版本白干一场。**

## 三、怎么办 —— 三条机制，不只靠文档

### 机制 1： CODEOWNERS（机器强制）

放在仓库根目录，GitHub 会自动要求对应负责人批准，绕不过去：

```
# 跨模块契约：提供方和调用方都必须批
/openapi/                   @A @B @C @D @E

# 各服务目录：只有负责人能批
/services/m1-service/       @B @A
/services/m2-service/       @C @A
/services/m3-service/       @D @A
/services/d-service/        @E @A

# 数据库迁移：模块负责人 + 工程化负责人
/**/db/migration/           @E @A

# 治理文档
/AGENTS.md                  @A
/docs/adr/                  @A
```

### 机制 2： PR 模板（逼人填完）

放 `.github/pull_request_template.md`，不填就没法解释：

```markdown
## 关联
需求编号：Mx-xxx ｜ closes #issue

## 改了什么 / 为什么

## 是否触及以下敏感区（勾了必须说明）
- [ ] 跨模块接口（若有 → 附契约文件 diff）
- [ ] 数据库 schema / 迁移（若有 → 附迁移与回退说明）
- [ ] 公共层 d-service
- [ ] 权限、审计、安全

## 验证
跑了哪些测试，结果如何。破坏实现后对应测试是否失败。

## 未解决问题与回滚方式
```

### 机制 3： CI 校验（自动化拦截）

`.github/workflows/contract-guard.yml`：契约文件被改而没有联席批准 → 直接红。

```yaml
name: contract-guard
on: pull_request
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }
      - name: 检测契约变更
        run: |
          git diff --name-only origin/${{ github.base_ref }}...HEAD > changed.txt
          if grep -q '^openapi/' changed.txt; then
            echo "CONTRACT_CHANGED=true" >> $GITHUB_ENV
            echo "::warning::跨模块契约被修改，需调用方与提供方共同批准"
          fi
      - name: 解析校验 OpenAPI
        if: env.CONTRACT_CHANGED == 'true'
        run: |
          pip install pyyaml openapi-spec-validator
          for f in $(git diff --name-only origin/${{ github.base_ref }}...HEAD | grep '^openapi/.*\.yaml$'); do
            openapi-spec-validator "$f" || exit 1
          done
      - name: 阻断未批准的契约变更
        if: env.CONTRACT_CHANGED == 'true' && ! contains(github.event.pull_request.labels.*.name, 'contract-approved')
        run: |
          echo "契约变更需要打 contract-approved 标签（由提供方+调用方确认后添加）"
          exit 1
```

## 五、一句话原则

**契约先行 → CODEOWNERS 强制谁批 → CI 拦截未批准的契约改动 → PR 模板逼出说明。**

四层里，**文档只是第一层，真正防冲突的是后三层机器机制**。
