## 二、依赖关系（谁卡谁）

| 前置 → 后继                              | 卡的是什么                              |
| ------------------------------------ | ---------------------------------- |
| ENG-01 → 全部任务                        | 没有仓库和进程，谁都动不了手                     |
| ENG-03 → ENG-05                      | 主数据落哪个 schema 要先定                  |
| **ENG-05 → M1-001**                  | 没有房间座位数据，B 的查询接口出不来（PD-002）        |
| **D-001 → M1-001 / M2-001 / M3-001** | 三个业务模块接口都要鉴权，JWT 方案不定就各写各的（PD-001） |
| **D-005 → M1-002**                   | 最长预约时长不能写死在代码里（PD-003）             |
| M1-001 → M1-002                      | 先能查到座位，才谈得上预约                      |
| 契约 INT-001 → M2-003、M2-004           | C 调 M1 占用/释放                       |
| 契约 INT-002 → M3-003、M3-004           | D 调 M1 下架/恢复                       |
| D-004 → 各模块写审计                       | 可后补，审计失败不阻断主业务                     |
| D-003 → M1-004                       | M1-004 本轮暂缓，不阻塞                    |

## 三、关键路径

```
ENG-01 仓库骨架
   └─ ENG-03 四 schema
        └─ ENG-05 主数据
             └─ M1-001 座位查询
                  └─ M1-002 整点预约
```

**这条链上任何一环延迟，M1 整体顺延。** 关键路径不在业务模块，在 E 的工程基座和主数据。

## 四、三组并行（谁不用等谁）

依赖关系里最有价值的信息，是**哪些事现在就能开始**：

| 并行线                 | 能不能现在开工    | 依据                                  |
| ------------------- | ---------- | ----------------------------------- |
| C 的 M2-003 / M2-004 | **能**      | 契约 INT-001 已冻结，可对 Mock 实现，不用等 B 的代码 |
| D 的 M3-003 / M3-004 | **能**      | 契约 INT-002 已冻结，同上                   |
| B 的 INT-001/002 实现  | **能**      | 契约已冻结，接口定义就是确定的                     |
| C 的 M2-001 / M2-002 | 能（等 D-001） | 本模块内部功能，与 M1 无关                     |
| D 的 M3-001 / M3-002 | 能（等 D-001） | 同上                                  |

**这就是契约先行的收益**：C 和 D 的跨模块部分，**不等 B 写代码，只等 B 冻结契约**。而契约已经冻结了。
